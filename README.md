# MaxxDev — maxxdev.ru

Сайт разработчика на Vue 3 + Vite: чёрная тема, оранжевые акценты, адаптивная верстка, анимации с поддержкой `prefers-reduced-motion`. Сервер Node.js принимает заявки и доставляет каждую на почту **и** в Telegram.

## Локальный запуск

Node.js 20.19+ или 22.12+.

```bash
npm ci
cp .env.example .env
```

Заполните серверные настройки в `.env`. Для локальной разработки установите `SITE_URL=http://localhost:4173`. В отдельных терминалах:

```bash
npm run dev:api
npm run serve
```

Откройте `http://localhost:4173`. Vite проксирует `/api` в Node.js на порту 3001. Настройки SMTP и бота не попадают в клиентскую сборку. Локальная форма с реальными настройками отправляет настоящие заявки.

```bash
npm test
npm run build
```

Тесты используют временные каталоги и имитацию отправки: реальные письма и сообщения не отправляются.

## Почта и Telegram

В `.env` укажите:

- `MAIL_TO` — адрес, куда получать заявки.
- `MAIL_FROM` — почтовый ящик отправителя.
- `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE` и при необходимости `SMTP_USER`, `SMTP_PASSWORD` — настройки почтового сервера.
- `TELEGRAM_BOT_TOKEN` — токен бота от BotFather.
- `TELEGRAM_CHAT_ID` — числовой ID чата получателя.
- `SITE_URL` — точный публичный адрес, обычно `https://maxxdev.ru`.

По [инструкции 1Gb.ru](https://www.1gb.ru/hosting_email.php), для отправки с VDS доступен `robots.1gb.ru:25` без авторизации из сети хостинга; отправитель должен быть зарегистрированным у провайдера почтовым ящиком. Эти значения уже внесены в пример. Если используете другую почту, замените SMTP-настройки по инструкции своего провайдера. Для SMTP с STARTTLS обычно используется порт 587 и `SMTP_SECURE=false`, для TLS с начала соединения — 465 и `true`.

Создайте бота через `@BotFather`, добавьте токен в `.env`, откройте бота и отправьте `/start`. Затем на сервере выполните:

```bash
npm run telegram:chat
```

Команда получает обновления и выводит ID доступных чатов, не отправляя сообщений и не печатая токен. Внесите нужный ID в `TELEGRAM_CHAT_ID`. Для группы добавьте туда бота и отправьте команду ему. Если у бота уже настроен webhook, `getUpdates` недоступен — используйте известный ID чата. [Документация Telegram Bot API](https://core.telegram.org/bots/api).

Не добавляйте `.env` в git. Он должен находиться только на сервере; `profile.email` в клиентском коде нужен лишь для необязательной публичной ссылки и не определяет получателя формы.

## Размещение на VDS

Ниже пример для Linux с systemd и nginx. Если на VDS уже есть панель или веб-сервер, адаптируйте конфигурацию к нему, не заменяя настройки других сайтов.

1. Направьте DNS домена на IP VDS, установите Node.js и nginx.
2. Разместите репозиторий в `/var/www/maxxdev.ru`. Выполните `npm ci`, `npm run build`, создайте `.env` из примера и заполните его. Сборка `dist/` и Node-сервер нужны вместе: статический хостинг сам по себе заявки не отправляет.
3. Создайте отдельного системного пользователя `maxxdev` и доступный ему каталог очереди:

```bash
sudo useradd --system --home /var/www/maxxdev.ru --shell /usr/sbin/nologin maxxdev
sudo mkdir -p /var/www/maxxdev.ru/var
sudo chown -R maxxdev:maxxdev /var/www/maxxdev.ru
sudo chmod 600 /var/www/maxxdev.ru/.env
sudo chmod 700 /var/www/maxxdev.ru/var
```

4. Скопируйте `deploy/maxxdev.service` в `/etc/systemd/system/maxxdev.service`. Проверьте путь к Node.js: пример использует `/usr/bin/node`.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now maxxdev
sudo systemctl status maxxdev
```

5. Подключите `deploy/nginx.conf` как конфигурацию сайта (например, `/etc/nginx/sites-available/maxxdev.ru` с ссылкой в `sites-enabled` на Debian/Ubuntu). Проверьте и перечитайте конфигурацию:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

6. Включите HTTPS перед использованием формы. Например, после установки Certbot с nginx-плагином:

```bash
sudo certbot --nginx -d maxxdev.ru -d www.maxxdev.ru
```

Выберите перенаправление HTTP на HTTPS. Основной адрес — `https://maxxdev.ru`, `www` перенаправляется на него. Порт 3001 слушает только `127.0.0.1`: наружу публикуется nginx на 80/443. В `.env` оставьте `SITE_URL=https://maxxdev.ru`.

7. Отправьте контрольную заявку с сайта и проверьте оба получателя. Принятие API не означает, что провайдер уже доставил письмо в папку входящих. Для диагностики смотрите `journalctl -u maxxdev` и статусы каналов в `var/contact-outbox/*.json`. После изменения `.env` перезапустите `sudo systemctl restart maxxdev`.

Для обновления сайта: `git pull`, `npm ci`, `npm run build`, `sudo systemctl restart maxxdev`.

## Как обрабатываются заявки

`POST /api/contact` проверяет поля, тип проекта, источник браузерного запроса и скрытое антиспам-поле. Ограничение — 5 попыток на IP за 10 минут, тело до 24 КБ. Это базовая защита; запросы с произвольного HTTP-клиента могут не содержать Origin.

Подтверждение в форме появляется только после записи заявки в серверную очередь. При ошибке поля сохраняются. Повтор той же заявки с тем же ID не создаёт второй записи. Во время отправки поля заблокированы. ID сохраняется для повтора в текущей вкладке; после перезагрузки страницы повтор создаст новую заявку.

Каждый канал имеет отдельный статус. При временном сбое повторяется только недоставленный канал, с интервалом от 30 секунд до часа. Длинный Telegram-текст разделяется на сообщения; успешно отправленные части отмечаются отдельно. После перезапуска службы очередь продолжает работу. При аварийном завершении между принятием сообщения провайдером и записью статуса возможен повтор; гарантию строго единственной доставки внешние API не предоставляют.

Завершённые заявки удаляются через 14 дней, незавершённые сохраняются до доставки. Лимит очереди — 500 незавершённых заявок; при заполнении API возвращает ошибку. Каталог `var/` содержит контакты посетителей, исключён из git и не обслуживается веб-сервером. Сохранность очереди зависит от диска VDS: учитывайте её в резервном копировании. Логи содержат ID и код ошибки без текста заявки, паролей и токена.

## Где менять содержание

- `src/App.vue` — сборка страницы и связь выбора услуги с формой.
- `src/components/layout/` — шапка и подвал.
- `src/components/sections/` — основные разделы страницы.
- `src/components/portfolio/` — карточка проекта, иллюстрация и диалог кейса.
- `src/components/contact/` — форма заявки.
- `src/composables/` — состояние формы, сохранение черновика, отправка и эффекты.
- `src/data/` — отдельные файлы профиля, проектов, услуг и цен.
- `src/services/contactApi.js` — HTTP-запросы к API заявок.
- `src/assets/styles/` — общие стили, адаптивность и стили разделов.
- `server/` — API, очередь и доставка.
- `deploy/` — примеры systemd и nginx.
- `.env` — приватные настройки сервера.

Перед публичным запуском замените декоративные иллюстрации проектов реальными скриншотами и проверьте описания кейсов.

## Устройство клиентской части

`App.vue` объединяет разделы и создаёт состояние формы через `useContactForm`. Услуги и цены сообщают о выборе платформы событием `select-platform`. Форма получает тот же контроллер через props, поэтому выбор услуги, восстановление черновика и повторная отправка используют единое состояние без глобальной шины событий.

Фильтр портфолио принадлежит `PortfolioSection`; карточка сообщает о выборе проекта событием `open`, а `ProjectDialog` управляет нативным диалогом и блокировкой прокрутки. Мобильное меню принадлежит `SiteHeader`. Эффекты первого экрана и появления разделов вынесены в `useHeroMotion` и `useScrollReveal` с очисткой при размонтировании.

CSS подключается из `src/assets/styles/main.css`. Стили разделены по назначению; порядок импорта сохраняет каскад, включая существующие общие селекторы и адаптивные правила. Контент редактируется в `src/data/`, независимо от шаблонов компонентов.
